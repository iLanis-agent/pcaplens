# PcapLens

A pcap (packet capture) inspector that runs entirely in the browser. Open `app.html`, drop a `.pcap` file (or pick a built-in preset), and get:

- a packet list (relative timestamps, endpoints, protocol, summary info)
- a per-packet layer tree: Ethernet (incl. 802.1Q VLAN), IPv4, IPv6, TCP, UDP, ICMP, ICMPv6 echo, ARP, DNS
- verified IPv4 header checksums (ok / BAD badge per packet)
- a hex dump of the selected packet
- container facts: byte order, microsecond vs nanosecond resolution, snaplen, link type, and warnings for truncated records/data

No server, no upload: parsing is 100% local JavaScript (`engine.js`, no dependencies).

## Live

https://ilanis-agent.github.io/pcaplens/

## File support

Classic libpcap format only (magic `d4 c3 b2 a1` / `a1 b2 c3 d4` for microsecond, `4d 3c b2 a1` / `a1 b2 3c 4d` for nanosecond; little- and big-endian). Only `LINKTYPE_ETHERNET` (1) is decoded; other link types load with a warning. pcapng is not supported.

## Tests

```
node tests/run_tests.js
```

Runs the shared engine over `tests/corpus/*.pcap` and compares every decoded field against `tests/expected.json`, which is generated by `tests/oracle.py` using real [scapy](https://scapy.net/) (`python3 tests/oracle.py`, needs `pip install scapy`). IPv4 header checksums are verified independently in plain Python inside the oracle. 500 assertions, all passing.

The corpus covers: a 5-packet TCP/HTTP flow, a DNS query+response (with name compression pointers), ARP who-has/is-at plus ICMP echo request/reply, IPv6 TCP and ICMPv6 echo, a nanosecond-resolution capture, and a truncated file that must produce a warning.

### Oracle deviation (disclosed)

`nano.pcap` has the same record bytes as `tcp_http.pcap` with only the global-header magic switched to the little-endian nanosecond value. scapy's `rdpcap` misreads nanosecond-resolution timestamps, so the oracle derives the nano expectations from the `tcp_http` expectations with the timebase changed to 1e9 (see the comment in `tests/oracle.py`). All other fields are read from the real file by scapy.

## Known limits

- TCP/UDP checksums are shown but not verified (pseudo-header needed; IPv4 header checksums ARE verified).
- DNS decodes the first question and first A-record answer; other RR types/counts are counted, not decoded.
- Non-Ethernet link types and pcapng are not decoded.
